# PRD — 방명록 안내 챗봇 (Guestbook RAG Chatbot)

## 1. 문제 정의

방명록 프로젝트(`conoc612-a11y/guestbook`)는 GitHub Pages + Render + Supabase로 만든 3계층 방명록입니다.
그러나 **방명록을 어떻게 쓰고, 삭제하고, 어떤 구조·보안·배포 원칙을 갖는지**를 문서로만 풀어 놓아,
관리자나 학습자가 "이 방명록은 어떻게 되어 있지?"라는 질문에 바로 답하기 어렵습니다.

이 챗봇은 **방명록 저장소의 지식을 근거로 대화형으로 안내**합니다.

## 2. 타겟 유저

| 유형 | 니즈 |
|---|---|
| 방명록 학습자 | 3계층 구조·데이터 흐름·보안·배포 이해 |
| 관리자 | 기능(쓰기/삭제)·API·DB 스키마 문의 |
| 과제 평가자 | RAG 파이프라인 + 판정 + 실험 표 데모 |

## 3. MVP 범위

- **근거 검색**: 방명록 지식 청크에서 관련 근거 k개 검색
- **출처 공개**: 답에 사용한 근거 조각(ID·섹션) 표시, 모달로 전문 확인
- **답변 생성**: 로컬 Ollama(기본) / Gemini(선택)로 스트리밍
- **자동 판정**: LLM-as-a-Judge가 근거 충실성·환각·출처 3루브릭 채점
- **약한 근거 경고**: 최고 유사도 < 0.55면 경고 배지
- **사람 피드백**: 👍/👎

## 4. 근거 자료

방명록 저장소의 실제 지식을 청크화 (`build_docs.py`):
- 개요(공개 방명록·로그인 제거) · 3계층 아키텍처 · 데이터 흐름
- 기능: 글 쓰기·읽기·삭제
- 보안: 비밀 키 분리 · XSS 방지 · RLS · 백엔드 검증
- 배포: Supabase DB · Render 백엔드 · GitHub Pages · 로컬 실행
- DB 스키마 · API 엔드포인트 · 제출 전 확인

스키마: `{ id (GB-NNN), text, url, section, vector }` — 768차원 `vector: number[]`.

## 5. 화면 구성

- 히어로(타이틀·설명)·엔진 선택(Ollama/Gemini)·정보 카드 3개
- 챗봇 영역(말풍선·출처 칩·판정 배지·피드백)
- Ollama 미연결 시 배너(설치·CORS 안내)

## 6. 수용 기준

| 기준 | 목표 |
|---|---|
| 대표 질문 6개 중 근거 있는 답변 | 3개 이상 |
| 근거 충실성 루브릭 평균 | 60점 이상 |
| 로컬 Ollama 연결 안내 | 차단 시 배너 표시 |
| 첫 방문 모델 캐시·진행률 | 표시 |
| GitHub Pages 배포 | 서브폴더에서 동작 |

**실측** (EVALUATION.md): 하이브리드 검색 k=15 Precision **1.00** — 기준 충족.

## 7. 제외 (비 MVP)

- 방명록 실제 CRUD 연동(이 챗봇은 "안내"만, 방명록 기능은 기존 앱이 담당)
- 다중 사용자·로그인
- 서버 측 임베딩(브라우저 임베딩 고정)

## 8. 기술

- Vite + React + TypeScript · 브라우저 ONNX(`@huggingface/transformers`) 임베딩
- embeddinggemma-300m(no_gather_q4) · 코사인 + BM25 하이브리드
- 로컬 Ollama(`qwen3.5:2b`) 스트리밍 / Gemini API
- GitHub Pages 정적 배포(`base: './'`)
