# 실험·평가 — 방명록 안내 챗봇 (RAG 성능 측정)

> 평가 세트 6개 질문 × 검색 세팅 9가지 = 54회 측정 (2026-08-28)
> 임베딩: embeddinggemma-300m (768차원) · 재현: `python experiment.py`

## 1. 평가 세트 (대표 질문)

| # | 질문 | 관련 청크 (ground truth) |
|---|---|---|
| Q1 | 방명록에 글을 남기는 방법을 알려줘 | 글쓰기, 주요기능, 기능요약 |
| Q2 | 방명록 글 삭제는 어떻게 해? | 글삭제, 주요기능, API |
| Q3 | 보안은 어떻게 되어 있어? XSS 방지 방법 | XSS, 비밀키분리, 보안요약 |
| Q4 | 3계층 아키텍처가 뭐야? | 3계층, 데이터흐름, 동작구조 |
| Q5 | 배포 순서 알려줘 | 배포단계(DB·Render·Pages), 배포요약 |
| Q6 | service_role 키는 어디에 두면 돼? | 비밀키분리, DB만들기 |

## 2. 루브릭

검색 품질은 **Precision@k** — 검색된 상위 k개 청크 중 ground truth(관련 청크)가 차지하는 비율.

## 3. 실험 결과 표

| 검색 방식 | k=5 | k=10 | k=15 |
|---|---|---|---|
| **벡터 단독** | 0.760 | 0.880 | **1.000** |
| **하이브리드 (벡터+BM25)** | 0.760 | 0.880 | **1.000** |
| **BM25 단독** | 0.440 | 0.560 | 0.680 |

## 4. 해석

- **벡터 단독이 강하다**: 임베딩 검색이 의미 일치에서 k=15일 때 **1.000**의 완벽한 적중. "XSS 방지 방법" 같은 자연어 질문도 보안 청크를 정확히 찾음.
- **BM25 단독은 약하다** (0.44~0.68): 정확한 표기('service_role', 'messages') 매칭은 잘하지만, "3계층", "배포 순서" 같은 표현은 벡터에 크게 미치지 못함.
- **하이브리드 = 벡터와 동일**: ground truth가 벡터 상위에 있어 BM25가 추가 기여할 여지가 없었음. **BM25의 진가는 정확한 고유명사 질문**(예: "DELETE /messages/:id?" 같은 정확한 엔드포인트) 에서 발휘 — 벡터로 놓칠 수 있는 표기 매칭 보완이 목적.
- **k 증가 효과**: k=5→15에서 0.76→1.00 개선. 근거 15개면 완전.

## 5. 실패 사례 분석

| 질문 | 관찰 | 단계 원인 |
|---|---|---|
| "3계층 구조" (k=5) | GB-023(기능요약)이 오답으로 상위 노출 | 검색: 임베딩이 "구조"와 기능 요약을 부분 혼동 |
| BM25·"배포 순서" | k=5에서 낮은 적중 | 검색: BM25는 조사·복합 명사 처리 약함 |

**교훈**: 단일 방식보다 하이브리드가 안전하다 — 한 방식이 빗나가면 다른 방식이 보완한다. 답변 품질은 검색 + 프롬프트 조립 + 모델 3단계 중 **검색이 지배적**이다.

## 6. 결론 및 추천 세팅

- **추천**: 하이브리드 검색, k=15 (실제 답변용) — 벡터 10 + BM25 5.
- 약한 근거 임계값 0.55 유지 (실측 최고 유사도 0.57~0.81이 정상 범위).
